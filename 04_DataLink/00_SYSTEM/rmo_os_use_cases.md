## ケース1: PTA（学校の親の会）

### 背景
- 学校数：1000名
- メンバー：200家庭（600～700人）
- 役員：10～15名
- 年度：4月～3月

### 問題点（Before RMO OS）

```
【毎年の課題】
1. 年度交代時の引き継ぎが属人化
   → 「前年度、○○さんがやってた」
   → 新役員が「何をするべきか」分からない

2. 総会資料が手作業で作成
   → Word で手作業 → 10～20時間
   → 毎年同じ形式なのに毎回ゼロから

3. 会計が透明でない
   → 領収書が散乱
   → 「去年の会費は？」が答えられない
   → 親から「会計が不透明」と指摘

4. 会議の議事録がばらばら
   → LINE グループで写真送信
   → メールで別送信
   → 統一されない

5. スケジュール管理が統一されない
   → 個人のカレンダー
   → LINE 通知
   → 参加確認が来ない
```

### RMO OS 導入後（After）

#### 年度開始時（4月）

**Step 1: 新年度を準備**

```
1. 前年度をテンプレート化
   → システムが前年度の「スケジュール」「メンバー」「事業」をコピー

2. 新役員情報を入力
   → 従来：手作業でメンバー入力 → 30分
   → RMO OS：CSV でインポート → 5分

3. 年間スケジュールを確認・修正
   → 前年度のスケジュール（学校行事、PTA行事）がすでに存在
   → 変更が必要な部分だけ修正
   → 従来：ゼロから入力 → 1時間
   → RMO OS：確認・修正のみ → 15分

4. リマインダー設定
   → 重要イベント 1 週間前に自動メール通知
   → スケジュール変更時に自動で再通知
```

**Result：年度準備が 1時間 → 30分に短縮**

---

#### 総会準備（3月）

**Step 1: 総会資料の自動生成**

```
【従来のプロセス】
1. メンバー名簿を確認（手作業）
   → 変更あったメンバーを修正
   → 30分

2. 会計数字を集計（Excel 手作業）
   → 収支報告書を作成
   → 45分

3. 事業実績をまとめる（手作業）
   → 去年のテンプレートをコピー
   → 新しい内容を入力
   → 1時間

4. PowerPoint/Word で資料作成
   → デザイン調整
   → 印刷確認
   → 2時間

合計：5～6時間、複数人で分担、最後に調整が必要

【RMO OS のプロセス】
1. 「総会資料生成」ボタンをクリック

2. 画面に「確認してください」と表示
   → メンバー一覧（自動抽出）
   → 会計データ（自動抽出）
   → 事業成果（自動抽出）
   → すべて確認・修正
   → 30分

3. テンプレート選択
   → 「PTA 標準テンプレート」を選択

4. プレビュー確認
   → レイアウトが正しいか確認
   → 不要な部分をカスタマイズ
   → 10分

5. 「生成」ボタンをクリック
   → PDF が自動生成
   → ダウンロード開始
   → 5分

合計：45分で完成、1人で対応可能、修正が少ない
```

**Result：総会資料作成が 5～6時間 → 45分に短縮**

---

#### 会議運営（毎月）

**Step 1: 事前準備**

```
【議題設定】
- 理事会議を開催する 1 週間前
- 「会議を新規作成」ボタン
- アジェンダを入力
  ├─ 議題1：学校との連携（担当：副会長）
  ├─ 議題2：運動会のサポート体制（担当：会長）
  └─ 議題3：会計報告（担当：会計）
- 参加者を指定（12名の理事）
- 日時・場所を設定

【自動通知】
- リマインダーが全理事に自動メール送信
- 議題が事前に共有される
- 準備が明確になる
```

**Step 2: 会議当日**

```
【タイマー機能】
- 各議題に時間を割り当て（15分、20分、10分）
- 進行中は画面に「あと◆分」と表示
- 時間超過をアラート

【議事録作成】
- タブレットで発言内容をメモ入力
- 決定事項を「決定」欄に記入
- アクション項目を「担当者」「期限」と一緒に記入
```

**Step 3: 会議後**

```
【AI 自動要約】
- テキストをシステムに送信（or 音声入力）
- Gemini API が自動要約
  → 「本会議で以下を決定した」
  → 「以下の実施項目がある」
- 手作業での要約作成が不要

【議事録配信】
- すべてのメンバーに自動メール配信
- アクション項目がある人には個別通知
- 期限 1 週間前に自動リマインダー

【記録保存】
- 過去の議事録をすべて検索可能
- 「去年はどうしてた？」が即座に確認可能
- 引き継ぎが簡単に
```

**Result：議事録作成・配信が 2～3時間 → 30分に短縮**

#### 会計管理（随時）

**Step 1: 支出申告**

```
【従来の方法】
- 領収書を持って会計担当に報告
- 会計担当が Excel に入力
- 手書きで金額確認
- 後で「どの項目だったっけ？」

【RMO OS の方法】
1. スマートフォンで領収書を写真撮影
2. アプリから「支出申告」
   - 写真アップロード
   - 科目選択（「消耗品費」など）
   - 金額入力（自動で写真から読み込み予定：OCR）
   - 説明（「6月 クッキー材料費」）
3. 「送信」
4. 会計担当に自動通知
5. 会計担当が確認 → 「承認」
6. 自動で記帳
```

**Step 2: 決算書の自動生成**

```
【従来の方法】
- 領収書をすべて確認
- Excel で科目別に分類
- 計算
- グラフ作成
- 決算書を作成
- 手間：4～5時間

【RMO OS の方法】
1. 「決算書を生成」ボタン
2. システムがすべての取引を自動集計
   - 科目別合計
   - 収支の差
   - 前年度との比較
3. PDF で自動生成
4. 手間：10分
```

**Result：会計処理が 80%削減**

---

### 最大の効果：誰でも運営可能に

```
【重要な変化】

Before：特定のメンバー（会長、会計など）の「属人知」に依存
       ↓
       新年度に「教えてくれる人がいない」と困る

After：すべてが「システムと記録」に依存
       ↓
       誰が役員になっても、システムをたどれば対応可能
       ↓
       新役員の学習曲線が大幅に短縮
       ↓
       「複雑で大変」という理由で役員を避ける傾向が減少
       ↓
       多くの親が役員に立候補するようになる
```

## ケース2: 自治会（地域運営）

### 背景
- 対象：1地区の自治会
- 世帯数：150世帯
- メンバー：50～60名
- 役員：5～7名
- 活動：月1回の役員会、年3～4回の総会、夏祭り、防災活動など

### 問題点（Before RMO OS）

```
【自治会の課題】
1. 高齢化で引き継ぎが困難
   → 80代の会長がシステムを理解していない
   → 新しい試みができない

2. 情報が老人会、婦人会などで分散
   → 統一された情報がない
   → 重複した連絡が発生

3. 会計が見えない
   → 「どこにお金を使ってるか知らない」と住民から指摘
   → 決算報告が複雑で理解しづらい

4. 会議の記録がない
   → 「去年は何を決めた？」が答えられない
   → 繰り返し同じ議論をしている

5. 若い世帯の参加が少ない
   → 情報が「掲示板」「回覧板」のアナログ中心
   → スマートフォンの親には届かない
```

### RMO OS 導入後（After）

#### 組織の一元管理

```
【従来】
老人会、婦人会、防災班、各種委員会
→ 各グループが独立
→ 情報が分散

【RMO OS】
すべてを一つのプラットフォームで管理
├─ 全体会議（役員会）
├─ 老人会 → スケジュール、会議、会計
├─ 婦人会 → スケジュール、会議、会計
├─ 防災班 → マニュアル、訓練記録
└─ その他の活動

効果：
- 情報の一元化
- 若い世帯へのお知らせが容易
- QR コードで「アクセス権限が必要な人だけ」参加可能
- 高齢者でもスマートフォンで確認可能
```

---

#### 会計の透明化

```
【会費の収支管理】

収入：世帯数×月200円 = 月30,000円
支出：公民館管理、防災活動、福祉活動、祭り

RMO OS での管理：
1. 毎月の収支を記録
   - 収入：会費、寄付金など
   - 支出：各活動ごとに記録（領収書添付）

2. 全住民向けに月次報告書を自動生成
   - 「今月の収支」
   - 「科目別内訳」
   - 「前年度との比較」
   - これを掲示板に貼り出す or メール配信

3. 年間決算書を自動生成
   - 総会時に配布
   - 「何にいくら使ったか」が一目瞭然

効果：
- 「会費はどこに使われているか」が透明に
- 不信感が減少
- 若い世帯の参加が増加
```

#### 夏祭りの運営

```
【従来の流れ】
1月：役員会で「今年も夏祭りをやる」と決定
3月：実行委員会設立
     ├─ メンバー選定（15名）
     └─ 役割分担（食べ物、音楽、看板など）
     ├─ 手作業で紙に役割を書く
     └─ 回覧板で周知

5月：企画会議
     ├─ 何をやるか決める
     └─ 議事録を紙で記録（あいまい）

7月：準備期間
     ├─ 資材調達：各自が買い物、領収書がバラバラ
     ├─ 役割確認：「あ、僕は何をするんだっけ？」
     └─ スケジュール確認：日程変更の通知ができない

8月15日：当日
        ├─ 予想外のことが発生
        └─ 誰が何をやるか混乱

【RMO OS での流れ】
1月：役員会でプロジェクト登録
     - 「2026年度 夏祭り」というプロジェクトを作成
     - 予算：500,000円
     - メンバー：15名を指定
     - スケジュール：自動で重要日程をカレンダーに追加
     - リマインダー：メンバーに自動通知

3月～7月：実行計画
     - 各委員会（食べ物班、音楽班など）がタスクを登録
     - タスク進捗が可視化される
     - 「あと◆日で○○班は何を完了する必要がある」が全員に見える

5月：企画会議
     - リッチテキストで議事録作成
     - 決定事項が「タスク」に自動変換
     - 担当者に自動通知

7月：準備期間
     - 資材購入の領収書をアップロード
     - 予算との差分が自動計算
     - 「あと◆◆円まで使える」が透明に
     - スケジュール変更があれば即座に通知

8月15日：当日
        - タスク確認画面で「今日誰が何をするか」が全員に見える
        - 突発的な変更もシステムで通知可能

【効果】
- 準備の見える化
- 当日のトラブル対応が容易
- 経験が蓄積される
```

#### 防災活動の記録と継承

```
【防災訓練の記録】

例：年1回の防災訓練（秋）

RMO OS での管理：
1. 防災マニュアルを「ドキュメント」として保存
   - 地域のハザードマップ
   - 避難経路
   - 集合場所
   - 連絡体制

2. 訓練実施記録
   - 参加者数
   - 実施内容
   - 問題点
   - 改善提案

3. 過去年度の記録と比較
   - 「去年の訓練で何がうまくいかなかった？」が即座に確認
   - 改善策を実行

【効果】
- 防災に対する継続的な取り組み
- 経験の蓄積で対応力が向上
- 新しく引き越してきた人も過去の記録から学習可能
```

## ケース3: 実行委員会（イベント運営）

### 背景
- イベント名：「宇土祭り」
- 期間：11月15日（土）～16日（日）
- メンバー：200～300名（ボランティア含む）
- 部門：20～30の運営チーム

### RMO OS での実行

#### 準備フェーズ（8月～10月）

```
【プロジェクト登録】
- 「宇土祭り 2026」をプロジェクト登録
- 予算：1,000万円
- スケジュール：
  ├─ 8月末：企画会議
  ├─ 9月中：演出品調達
  ├─ 10月中：当番の割り当て
  └─ 11月15日：本番

【チーム編成】
20～30のチーム（食べ物、ステージ、看板、駐車場など）
各チームがRMO OSで自分たちのタスクを管理
└─ タスク完了度が全体で見える

【会計管理】
- 各チームが支出を記録
- 領収書をアップロード
- 予算監視：各チームで予算上限が自動表示
- 追加予算が必要なら稟議システムで申請可能

【会議管理】
- 週1回の進捗会議
- 議事録から「決定事項」「アクション」を自動抽出
- 関連チームに自動通知
```

---

#### 本番フェーズ（11月15日～16日）

```
【リアルタイム進捗管理】
- 各チームが「進捗」をリアルタイム更新
  └─ 「食べ物コーナーの準備が完了」
  └─ 「来場者が予想を超えている」
  └─ 「駐車場が満杯」

- 総合司令室で全体進捗を見える化
  └─ 問題が発生していないか即座に確認
  └─ 対応が必要なら指示を出す

【当番管理】
- 当番表をスマートフォンで確認
- 「次は◆◆班がステージを担当」
- 欠席者が出た場合、代替者を即座に指定

【来場者向けアナウンス】
- QR コード で祭り情報サイトへアクセス
  └─ 各コーナーの場所
  └─ イベントスケジュール
  └─ リアルタイム混雑情報
```

---

#### 事後処理（11月中旬以降）

```
【成果報告書の自動生成】
- 来場者数
- 売上金額
- 使用金額
- ROI（投資対効果）
- 参加者数、ボランティア従事時間

【アンケート集計】
- 来場者アンケート
- 実行委員アンケート
- AI が自動要約＋改善提案

【知見の蓄積】
- 来年度へのノウハウ記録
- 「うまくいったこと」「失敗したこと」を記録
- 来年度の企画会議で参照可能
```

## ケース4: RMO OS導入による組織変革

### 宇土市全体への波及

#### 市民参加の活性化

```
【情報の見える化による効果】
Before：
- 市民は「自治会が何をしているのか知らない」
- 「PTA は何に会費を使っているのか不透明」
- 「イベント情報がどこにあるか分からない」

After：
- すべての組織情報が市民ポータルで見える化
- 「この祭りに参加したい」
- 「この活動を手伝いたい」
- という動きが増加

【参加者の増加】
- 年1回の祭りだけ参加 → 年3～4回の活動に参加
- 「何をやっているのか分からない」 → 「こんなことをやってるんだ」と興味が増加
- 特に若い世帯の参加が増加
```

#### 行政との連携強化

```
【市の視点】
Before：
- 各PTA、自治会が何をしているのか把握不十分
- 市民参加施策を打ちたいが、どの団体に働きかけるべきか判断困難

After：
- すべての組織のデータが市で見える化（適切な権限管理の下で）
- どの地域が活動的か一目瞭然
- 市の施策と各団体の活動を連動させやすくなる

【例：移住・定住OS との連携】
- 移住者が「この地域の自治会活動は活発か」を RMO OS で確認可能
- 活発な地域への移住意欲が高まる
- 地域の活動が移住者の決定要因になり得る
```

【組織レベルの変化】

■ 効率化

■ 透明性
- 会計が完全に透明化

■ 継続性

- 新役員が学習しやすい
- 組織が「人」に依存しなくなる

■ 参加者増
- 情報が見える化される
- 「複雑で分からない」が減少
- 若い世代の参加が増加

【市レベルの変化】

■ 市民協働の活性化

- 市民参加機会が拡大

■ 行政の意思決定が高速化
- 市民の動向がデータで把握可能
- 施策立案がしやすくなる

■ 移住・定住促進
- 「地域の活動が活発」が移住の判断要因に
- 移住者の定住率が上昇
```

## 導入チェックリスト

### 各組織がRMO OSを導入する際のステップ

```
□ Step 1: 説明会への参加（30分）
