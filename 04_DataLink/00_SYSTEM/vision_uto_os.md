# 宇土OS - 自治体デジタルプラットフォーム思想

## 1. ビジョン（Vision）

宇土OSは、宇土市における「行政・議会・市民・地域経済」を横断的につなぐ、統合型デジタルプラットフォームである。その本質は単なる情報整理ツールではなく、「意思決定の構造」を再設計するシステムである。

現在の自治体運営は、縦割り構造・情報分断・属人的判断に依存している。この状態では、人口減少時代における迅速かつ合理的な意思決定は不可能である。宇土OSは、この構造そのものを変革し、「データに基づく意思決定」を標準化することを目的とする。

また、市民にとっては「必要な情報に即座にアクセスできる状態」を実現し、制度や支援を"使えるもの"へと変換する。行政にとっては「判断のための統合データ基盤」、議会にとっては「政策判断の可視化基盤」として機能する。

最終的に宇土OSは、「自治体を一つのOSとして再定義する」ことを目指す。制度・データ・意思決定を統合し、持続可能な地域経営を実現するための基盤である。

---

## 2. コア思想（Core Philosophy）

- **原則1: 構造がすべてを決める**  
  問題は個別事象ではなく構造に存在する。情報・業務・意思決定を構造化することで、自治体は進化可能になる。

- **原則2: データは資産であり、統合されて初めて価値を持つ**  
  財政データ、議会データ、市民サービス情報などは分散している限り無価値に近い。統合・構造化により意思決定資源へ変換する。

- **原則3: 市民をインターフェースの中心に置く**  
  行政都合ではなく、市民視点で設計されたUI/UXを持つことで、制度は初めて機能する。宇土OSは「市民が使える行政」を実現する。

## 3. システムアーキテクチャ（Architecture）

### レイヤー構成

```
┌─────────────────────────────────────┐
│ 00_System (System Layer)            │ ← ビジョン・戦略
├─────────────────────────────────────┤
│ 04_DataLink (Data/Integration Layer)│ ← Projects, Decisions, Logs
├─────────────────────────────────────┤
│ 03_Knowledge (Knowledge Base)       │ ← Business, Tech, General
├─────────────────────────────────────┤
│ 01_Inbox (Staging Area)             │ ← ChatGPT Imports等
└─────────────────────────────────────┘
```

### 各レイヤーの役割：

- **00_System**  
  ビジョン、戦略、意思決定の定義。宇土OSの方向性を固定する最上位レイヤー。

- **04_DataLink**  
  実行レイヤー。議会活動、行政プロジェクト、意思決定履歴、ログを蓄積。  
  → 宇土OSの"現実"がここに集約される。

- **03_Knowledge**  
  汎用知識の蓄積。ビジネス、技術、制度理解など、意思決定の材料となる知識を管理。

- **01_Inbox**  
  外部情報の取り込み口。ChatGPTログ、メモ、PDFなど未整理データを一時保管。

## 4. 実装例（実際の運用）

### Admin/Regional グループ（04_DataLink/projects）

- 宇土市議会の一般質問データの構造化
- 部局別回答傾向の分析
- 市政課題（人口減少、財政、インフラ）のプロジェクト管理
- 政策提案の履歴管理と意思決定ログ化

👉 議会活動を「データ化された意思決定プロセス」に変換

---

### Business グループ（03_Knowledge/business）

- ウトマチ百貨店のブランド戦略
- 地域商社モデルの設計
- 生産者と消費者をつなぐ流通構造
- EC（Amazon）販売戦略

👉 地域経済の再設計ナレッジを蓄積

---

### Tech グループ（03_Knowledge/tech）

- Next.js / Firebase アーキテクチャ
- e-Stat API データ取得
- PDF構造化（決算・予算）
- AI（Gemini / ChatGPT）連携

👉 宇土OSを実装するための技術基盤

## 5. 統合戦略（Integration Strategy）

### ChatGPT データの役割

これまでの1,000件以上の対話ログは、
- 思考プロセス
- 意思決定の履歴
- 仮説検証の記録

として機能する。

これらを以下に再配置する：

- Inbox → 未整理ログ
- Knowledge → 汎用知識化
- DataLink → 実行プロジェクト化

👉 ChatGPTは「思考ログ生成装置」として位置付ける

---

### 複数AI活用

- ChatGPT：構造設計・文章生成・戦略整理
- Claude：長文分析・資料整理
- Gemini：アプリ連携・リアルタイム処理

👉 AIを役割分担し、単一依存を避ける

---

### 外部システム連携

- **Obsidian**：思考・設計OS
- **Firestore**：実データベース
- **Google Drive**：資料ストレージ
- **Next.js**：市民向けUI

👉 「思考・データ・UI」を分離しつつ統合

---

## 6. 実行ロードマップ（Roadmap）

- **フェーズ1（現在）**  
  知識の統合と体系化（Obsidian構築）

- **フェーズ3**

- **フェーズ4**  
  自治体間連携プラットフォーム化（横展開）
