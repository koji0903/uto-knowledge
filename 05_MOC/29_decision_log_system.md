# Decision Log System

重要な意思決定を記録・追跡・学習するシステム。

## 目的

- **決定の根拠を残す** — なぜこの判断をしたのか
- **AI の判定プロセスを記録** — 複数 AI の見方を比較
- **User による承認を可視化** — 誰が承認したか、いつ
- **過去の判定から学習** — 同様の判断時に参照可能
- **AI 信頼性を構築** — 判定根拠が明確なら信頼できる

## 基本概念

### Decision の定義

```
重要な判断 = 複数の選択肢から1つを選ぶこと

例：
- プロジェクトの優先度決定
- 資源配分の判定
- 大きな設計変更の承認
- リスク対応方針の決定
- 新規データリンク実装の判定
```

### 記録すべき決定

| 決定種別 | 例 | 記録義務 |
|---------|-----|--------|
| **戦略・ポリシー** | プロジェクト優先度、リソース配分 | ✅ 必須 |
| **大規模設計** | アーキテクチャ変更、新 collection 追加 | ✅ 必須 |
| **リスク対応** | セキュリティ対応、コンプライアンス | ✅ 必須 |
| **重要なデータ変更** | DataLink の大規模更新 | ✅ 必須 |
| **AI 間の不一致** | Claude と Gemini の意見が割れた | ✅ 必須 |
| **小さな改善** | ドキュメント修正、typo 直し | ❌ 不要 |

## ステータスの遷移

```
draft (作成中)
  ↓
proposed (複数案提示)
  ↓
approved (User 承認)
  ↓
implemented (実装完了)
  ↓
archived (完了・参考用)
```

### ステータスの意味

| ステータス | 意味 | 次のアクション |
|-----------|------|-------------|
| **draft** | 下書き中、複数案を検討中 | 案をまとめる |
| **proposed** | 複数案を提示、User待ち | User が選択・承認 |
| **approved** | User 承認済み | 実装開始 |
| **implemented** | 実装完了、動作確認済み | 振返り実施 |
| **archived** | 過去の参考用 | 類似決定時に参照 |

## AI 参加パターン

### パターン 1: 複数 AI 協業

```
1. Claude が複数案を分析
2. Gemini が外部情報を補足
3. ChatGPT が実装可能性を評価
4. User が最終判断
5. 決定ログに全視点を記録
```

### パターン 2: Claude リード

```
1. Claude が深い分析 → 複数案提示
2. User が承認
3. ChatGPT が実装支援
```

### パターン 3: Gemini リード

```
1. Gemini がリサーチ → 選択肢提示
2. Claude が戦略分析
3. User が判定
```

## 決定ログとの連携

### 同期ログとの違い

| 項目 | 決定ログ | 同期ログ |
|------|---------|---------|
| **記録対象** | 「何を決めたか」 | 「何を実行したか」 |
| **タイミング** | 決定時 | 実行時 |
| **内容** | 判断プロセス、複数案比較 | 実行内容、ステータス変更 |
| **保存先** | `04_DataLink/decisions/` | `04_DataLink/logs/` |

### 連携例

```
決定ログ: 「プロジェクト X に予算 100万 を配分」
  ↓ (決定に基づいて実行)
同期ログ: 「プロジェクト X の予算を Firestore に同期」
  ↓ (複数の同期ログが1つの決定を実装)
```

## よくある質問

### Q1: 小さな判断もログに残すべき？

A: **いいえ**。以下の基準で判定：

- 複数の選択肢がある？（例：yes/no は記録不要）
- 重要な影響がある？（システム全体 or 特定コンポーネント）
- 逆転困難？（後で変更しにくい）

上記すべてに YES なら記録。

### Q2: 実装後に決定を変更したら？

A: 新しい決定ログを作成：

```
決定_20260510_001: 「オプション A を採択」
  → 実装後に問題が発見
決定_20260515_001: 「オプション B に変更」
  → 過去と新規の決定を関連付ける
```

### Q3: AI の判定が間違っていたら？

A: **それこそが学習機会**。振返りセクションに記録：

```
【振返り】

期待: 低リスクで実装できる
結果: 予想外の複雑さで 2倍の時間がかかった

原因: Claude の設計案では X の相互依存性を見落とした

学習: 今後の設計は以下をチェック：
  - 複雑さのレベル確認
  - Gemini で競合製品も調査
  - ChatGPT に実装例を確認させる
```
