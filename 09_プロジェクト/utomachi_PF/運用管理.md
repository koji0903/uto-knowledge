# 運用・イベント・インシデント管理

[[overview|Utomachi Platform]] の運用システムの中核。リアルタイムイベント検出、インシデント対応、監査ログ。

## 1. Event (OSEvent)

**ファイル**: src/types/identity.ts

システム監視による自動検出イベント。

### データスキーマ

```typescript
interface OSEvent {
  id?: string;
  
  organizationId?: string;
  workspaceId?: string;
  domain?: DomainType;
  
  // イベント定義
  type: string;
  title: string;
  description?: string;
  
  // 重要度・ステータス
  severity: 'info' | 'warning' | 'critical';
  status: 'active' | 'resolved' | 'ignored';
  
  // ソース・関連付け
  source?: string;
  relatedEntityType?: string;
  relatedEntityId?: string;
  operationTaskId?: string;
  
  // メタデータ
  metadata?: {
    autoGenerated?: boolean;
    signalValue?: number;
    threshold?: number;
  };
  
  createdAt?: Timestamp;
  resolvedAt?: Timestamp;
}
```

### イベント種別例 (予測)

| 種別 | 重要度 | 説明 | 自動検出 |
|------|--------|------|---------|
| `water_quality_alert` | warning | 水質異常検出 | ✓ MonitoringRule |
| `nori_growth_anomaly` | warning | ノリ成長異常 | ✓ Threshold超過 |
| `market_price_surge` | info | 市場価格急騰 | ✓ MarketTrend |
| `staff_shortage` | critical | スタッフ不足 | ✓ Staffing監視 |
| `shipment_delay` | warning | 出荷遅延 | ✓ Task超期 |

### ステータス遷移

```
active (新規発生)
  ├→ resolved (対応完了)
  └→ ignored (無視判定)
```

## 2. Incident (OSIncident)

**ファイル**: src/types/identity.ts

複数イベントを統合した重大事象。インシデント対応ワークフロー統制。

### データスキーマ

```typescript
interface OSIncident {
  id?: string;
  
  organizationId?: string;
  workspaceId?: string;
  domain?: DomainType;
  
  // インシデント定義
  title: string;
  description?: string;
  
  // 重要度・ステータス
  severity: 'low' | 'medium' | 'high' | 'critical';
  status: 'open' | 'investigating' | 'responding' | 'resolved' | 'closed';
  
  // 関連付け
  relatedEventIds?: string[];
  relatedTaskIds?: string[];
  commanderUid?: string;
  
  // タイムスタンプ
  startedAt?: Timestamp;
  resolvedAt?: Timestamp;
  
  metadata?: {
    autoGenerated?: boolean;
    source?: string;
  };
  
  createdAt?: Timestamp;
}
```

### ステータス遷移フロー

```
open (新規報告)
  ↓
investigating (原因調査)
  ↓
responding (対応実施)
  ↓
resolved (解決確認)
  ↓
closed (クローズ)
```

### インシデント例（ノリ養殖）

| シナリオ | 重要度 | 対応 |
|---------|--------|------|
| 水温急低下 + ノリ白化 | high | 加温・フィード調整・出荷検討 |
| スタッフ複数欠勤 | critical | リソース動員・外注手配 |
| 出荷先からクレーム | medium | 品質調査・代替品手配 |

## 3. OperationTask

**ファイル**: src/types/identity.ts

イベント・インシデント対応の具体的なアクション。進捗管理・割り当て。

### データスキーマ

```typescript
interface OperationTask {
  id?: string;
  
  organizationId?: string;
  workspaceId?: string;
  domain?: string;
  
  // タスク定義
  title: string;
  description?: string;
  
  // 割り当て
  assignedTo?: string;
  assignedBy?: string;
  
  // ステータス・優先度
  status: 'pending' | 'assigned' | 'monitoring' | 'in_progress' | 'completed' | 'cancelled' | 'escalated';
  priority?: 'low' | 'medium' | 'high' | 'critical';
  
  // 期限・エスカレーション
  dueAt?: Timestamp;
  completedAt?: Timestamp;
  escalationLevel?: number;
  
  // 関連付け
  relatedEntityType?: string;
  relatedEntityId?: string;
  
  metadata?: {
    source?: string;
    autoGenerated?: boolean;
  };
  
  createdAt?: Timestamp;
}
```

### ステータス遷移

```
pending (未割り当て)
  ↓
assigned (割り当て済み)
  ├→ monitoring (進捗監視)
  └→ in_progress (実施中)
     ↓
   completed (完了)
   
OR
escalated (エスカレーション)
  → 上位層へ
```

## 6. OperationalMemory

**ファイル**: src/types/identity.ts

インシデント対応の知見・教訓の記録。組織学習の基盤。

### データスキーマ

```typescript
interface OperationalMemory {
  id?: string;
  
  organizationId?: string;
  workspaceId?: string;
  domain?: string;
  
  // 分類
  category: 'incident_response' | 'quality_control' | 'marine_condition' | 'shipment' | 'processing' | 'operations';
  
  // ドキュメント
  title: string;
  summary?: string;
  
  // SROIL フレームワーク
  situation?: string;       // どんな状況だったか
  response?: string;        // どう対応したか
  outcome?: string;         // 結果はどうだったか
  lessonsLearned?: string;  // 何を学んだか
  
  // 関連付け
  relatedIncidentIds?: string[];
  relatedEventIds?: string[];
  relatedTaskIds?: string[];
  
  authorUid?: string;
  tags?: string[];
  
  metadata?: {
    source?: string;
    autoGenerated?: boolean;
  };
  
  createdAt?: Timestamp;
}
```

### 記録例

```
Title: "水温低下対応プロトコル確立"
Category: incident_response

Situation:
  予期せぬ水温低下により、48時間で多数のノリ白化発生。
  スタッフは対応経験不足で、初動が遅延。

Response:
  1. 加温設備フル稼働
  2. 栄養フィード調整 (尿素→リン酸)
  3. 出荷予定をの延期検討・実施

Outcome:
  48時間で水温が+2°C改善。
  白化の進行が停止し、5日後に出荷実施。
  損失額を約30%削減。

Lessons Learned:
  - 水温センサーアラート閾値を±1°Cに引き下げ
  - スタッフ向け水温対応マニュアル作成・訓練実施
  - 加温能力の増強計画を提案
```

## 7. 監視ルール (MonitoringRule)

**ファイル**: src/types/identity.ts

自動イベント生成のルール定義。閾値監視。

### データスキーマ

```typescript
interface MonitoringRule {
  id?: string;
  
  organizationId?: string;
  
  // ルール定義
  title: string;
  description?: string;
  
  metricKey: string;              // 監視対象メトリクス
  operator: 'gt' | 'gte' | 'lt' | 'lte' | 'eq';
  threshold: number;
  
  severity: 'info' | 'warning' | 'critical';
  
  eventTitle: string;
  eventDescription?: string;
  
  enabled: boolean;
  
  metadata?: {
    autoGenerated?: boolean;
  };
  
  createdAt?: Timestamp;
}
```

### 監視ルール例

| メトリクス | 演算子 | 閾値 | 重要度 | 備考 |
|-----------|--------|------|--------|------|
| water_temp | lt | 15 | critical | ノリ養殖最低温度 |
| dissolved_oxygen | lt | 5 | warning | 酸欠リスク |
| salinity | gt | 35.5 | info | 異常値検出 |
| task_overdue_count | gt | 5 | critical | タスク積み上がり |
| staff_shortage | eq | 1 | critical | 人員不足 |

## 実装例

### イベント自動検出 (推定)

```typescript
// MonitoringRule に基づき、
// リアルタイムメトリクスをチェック

if (waterTemp < 15) {
  // OSEvent 作成
  const event = createEvent({
    type: 'water_temp_critical',
    title: '水温が危機的に低下',
    severity: 'critical',
    metadata: { currentValue: waterTemp, threshold: 15 }
  });
  
  // イベント数が多い場合、自動インシデント作成
  if (recentEventCount > 3) {
    const incident = createIncident({
      title: 'ノリ養殖環境異常',
      relatedEventIds: [event.id, ...],
      severity: 'high'
    });
  }
}
```

### タスク自動割り当て (推定)

```typescript
// インシデント作成時、対応タスクを自動生成
const tasks = [
  createTask({
    title: '水温回復対応',
    assignedTo: 'farm_manager',
    priority: 'critical',
    dueAt: now + 1hour
  }),
  createTask({
    title: 'ノリ品質調査',
    assignedTo: 'quality_team',
    priority: 'high',
    dueAt: now + 6hours
  })
];
```
