# 意思決定支援・戦略実行システム

[[overview|Utomachi Platform]] の AIアシスト型意思決定フレームワーク。

## 1. Decision Support Suggestion (DecisionSupportSuggestion)

**ファイル**: src/types/identity.ts

**役割**: インシデント・イベント発生時の提案生成。AI (Google Generative AI) で作成。

### データスキーマ

```typescript
interface DecisionSupportSuggestion {
  id?: string;
  
  organizationId?: string;
  
  // 関連付け
  relatedIncidentId?: string;
  relatedEventId?: string;
  relatedMemoryIds?: string[];
  
  // 提案内容
  title: string;
  reason?: string;
  suggestedActions?: string[];
  
  confidence?: number;        // AI信信度 (0.0-1.0)
  
  metadata?: {
    generatedBy?: string;     // 'claude', 'gpt', etc.
    autoGenerated?: boolean;
  };
  
  createdAt?: Timestamp;
}
```

### 実装参考

**コンポーネント**: src/components/AISuggestionCard.tsx
- AI提案の表示
- 信信度表示
- 提案のアクセプト/リジェクト機能

### 生成フロー（推定）

```
Event/Incident 発生
  ↓
関連する OperationalMemory を検索
  ↓
Google Generative AI に入力
  - 現在のコンテキスト
  - 類似の過去事例
  - 監視ルール・推奨プラクティス
  ↓
DecisionSupportSuggestion 作成
  ↓
UI に表示
```

## 2. Response Scenario (ResponseScenario)

**ファイル**: src/types/identity.ts

**役割**: インシデント対応の複数シナリオモデリング。影響予測。

### データスキーマ

```typescript
interface ResponseScenario {
  id?: string;
  
  organizationId?: string;
  
  // 関連付け
  relatedIncidentId?: string;
  relatedWorkflowId?: string;
  
  // シナリオ定義
  title: string;
  description?: string;
  
  strategyType: 'monitor_only'
              | 'accelerate_response'
              | 'increase_staffing'
              | 'shipment_adjustment'
              | 'processing_adjustment'
              | 'manual_custom';
  
  // 影響予測
  impacts?: ScenarioImpact[];
  
  confidence?: number;        // 予測信信度
  recommended?: boolean;      // AI推奨フラグ
  
  metadata?: {
    generatedBy?: string;
    autoGenerated?: boolean;
  };
  
  createdAt?: Timestamp;
}
```

### ScenarioImpact

```typescript
interface ScenarioImpact {
  metricKey: string;
  
  currentValue?: number;
  projectedValue?: number;
  delta?: number;
  
  direction?: 'improve' | 'worsen' | 'neutral';
  explanation?: string;
}
```

### シナリオ例（ノリ養殖）

#### シナリオ 1: Monitor Only (現状維持監視)

```
Title: "状況監視継続"
Strategy: monitor_only
Confidence: 0.6

Impacts:
  - water_temp: 16°C → 16.2°C (improve)
  - nori_health: 60% → 65% (improve)
  - staff_workload: high → high (neutral)
  - cost_impact: ¥0 (neutral)

Explanation:
  現在の加温設備で自然回復を待つ。
  リスク：回復が遅延する可能性。
```

#### シナリオ 2: Accelerate Response (積極対応)

```
Title: "加温・フィード調整"
Strategy: accelerate_response
Confidence: 0.85

Impacts:
  - water_temp: 16°C → 18°C (improve) ⭐
  - nori_health: 60% → 78% (improve) ⭐
  - staff_workload: high → very_high (worsen)
  - cost_impact: ¥150,000 (worsen) ⭐

Explanation:
  加温設備フル稼働 + 栄養フィード強化。
  48時間で水温+2°C達成。ノリ健全性を78%に回復。
  追加コスト：¥150,000 (電費 + 栄養料)
```

#### シナリオ 3: Shipment Adjustment (出荷調整)

```
Title: "出荷スケジュール延期"
Strategy: shipment_adjustment
Confidence: 0.7

Impacts:
  - water_temp: 16°C → 16.2°C (neutral)
  - nori_health: 60% → 75% (improve)
  - shipment_delay: 0日 → 3日 (worsen) ⭐
  - cost_impact: ¥−100,000 (improve) ⭐

Explanation:
  白化の進行を止め、自然回復を待つ。
  3日の出荷延期で品質回復。
  メリット：追加コスト不要
  デメリット：顧客への納期遅延通知
```

## 3. Predictive Simulation (PredictiveSimulation)

**ファイル**: src/types/identity.ts

**役割**: メトリクスの短期予測。トレンド分析。

### データスキーマ

```typescript
interface PredictiveSimulation {
  id?: string;
  
  organizationId?: string;
  
  // 予測対象
  metricKey?: string;
  
  // トレンド予測
  trend?: 'stable' | 'increasing' | 'decreasing' | 'volatile';
  
  currentValue?: number;
  predictedValue?: number;
  confidence?: number;       // 予測信信度 (0.0-1.0)
  
  explanation?: string;
  
  basedOnSnapshots?: string[];  // RegionalStateSnapshot 参照
  
  metadata?: {
    generatedBy?: string;
  };
  
  createdAt?: Timestamp;
}
```

### 予測例

```
Metric: water_temp
Current: 16.0°C
Predicted (24h): 16.8°C
Trend: increasing
Confidence: 0.78

Explanation:
  過去7日の気象データ、日中気温、
  海流パターンから推定。
  明日の最高気温が2°C上昇見込み。
```

```
Metric: nori_growth_rate
Current: 2.1cm/week
Predicted (1week): 3.5cm/week
Trend: increasing
Confidence: 0.82

Explanation:
  水温回復 + 栄養フィード投与の効果。
  ノリ成長が急速に加速する見込み。
```

## 4. Decision Log (DecisionLog)

**ファイル**: src/types/identity.ts

**役割**: 実際の意思決定の記録。後の評価・監査に活用。

### データスキーマ

```typescript
interface DecisionLog {
  id?: string;
  
  organizationId?: string;
  
  // 決定内容
  decisionType?: 'monitoring'
                | 'incident_response'
                | 'workflow_control'
                | 'shipment_adjustment'
                | 'staffing'
                | 'processing'
                | 'manual';
  
  title?: string;
  description?: string;
  rationale?: string;            // 決定根拠
  
  // シナリオ参照
  selectedScenarioId?: string;
  
  // 関連付け
  relatedIncidentId?: string;
  relatedWorkflowId?: string;
  relatedEventId?: string;
  
  // 決定者
  decidedBy?: string;            // ユーザーID
  decidedByName?: string;
  
  // 予想影響
  impacts?: {
    expectedOutcome?: string;
    expectedRisk?: string;
  };
  
  metadata?: {
    generatedFrom?: string;       // 'ai_suggestion', 'manual_override' など
  };
  
  createdAt?: Timestamp;
}
```

### 決定ログ例

```
Title: "ノリ養殖環境異常への対応決定"
Type: incident_response

Rationale:
  "加温・フィード調整（シナリオ2）が、
   リスク・コスト・効果のバランスで最適と判断。
   自然回復だけでは回復が遅延するリスク高い。"

SelectedScenario: scenario_2 (Accelerate Response)

DecidedBy: farm_manager (A. Tanaka)

ExpectedOutcome:
  "48時間で水温+2°C達成、
   ノリ健全性を60%→78%に回復。
   当初予定通りの出荷実現。"

ExpectedRisk:
  "加温能力の上限に達する可能性。
   複数ロットでの同時対応不可。"

CreatedAt: 2026-05-10 14:45:00
```

## 5. Outcome Evaluation (OutcomeEvaluation)

**ファイル**: src/types/identity.ts

**役割**: 決定の実績評価。意思決定精度の改善。

### データスキーマ

```typescript
interface OutcomeEvaluation {
  id?: string;
  
  organizationId?: string;
  
  // 評価対象
  relatedDecisionId?: string;
  relatedIncidentId?: string;
  relatedWorkflowId?: string;
  
  // 評価内容
  title?: string;
  summary?: string;
  
  evaluationResult?: 'successful' | 'partially_successful' | 'failed' | 'unknown';
  
  // 期待 vs 実績
  expectedOutcome?: string;
  actualOutcome?: string;
  
  expectedRisk?: string;
  actualRisk?: string;
  
  // メトリクス比較
  metrics?: {
    incidentDelta?: number;
    workflowDelta?: number;
    eventDelta?: number;
    operationalLoadDelta?: number;
  };
  
  // 評価者
  evaluatorUid?: string;
  evaluatorName?: string;
  evaluatedAt?: Timestamp;
  
  metadata?: {
    generatedBy?: string;
    autoGenerated?: boolean;
  };
  
  createdAt?: Timestamp;
}
```

### 評価例

```
Related Decision: decision_log_xyz

Title: "ノリ養殖環境異常への対応結果評価"

Evaluation Result: SUCCESSFUL ✓

Expected Outcome:
  "48時間で水温+2°C達成、ノリ健全性78%回復"

Actual Outcome:
  "実績：
   - 24時間で+1.8°C達成
   - 48時間で+2.2°C達成
   - ノリ健全性を78%に回復
   - 当初予定通り5/15に出荷実施
   - クレーム報告なし"

Expected Risk: "加温能力の上限に達する可能性"
Actual Risk: "発現せず。余裕で対応可能。"

Metrics:
  - Incident Active Count: 3 → 0 (resolved)
  - Event Active Count: 5 → 0 (resolved)
  - Staff Workload: very_high → normal (normalized)

Evaluator: Farm Director (B. Sato)
Evaluated At: 2026-05-15 18:00:00

## 学習フィードバック

→ このケースは OperationalMemory に格納
→ 将来の類似イベント検出時に DecisionSupportSuggestion で参照
→ 意思決定精度の向上
```

## 6. Outcome Impact Propagation (RegionalImpactPropagation)

**ファイル**: src/types/identity.ts

**役割**: 決定の波及効果分析。地域経済への影響追跡。

### データスキーマ

```typescript
interface RegionalImpactPropagation {
  id?: string;
  
  organizationId?: string;
  
  // 影響源
  sourceEntityType?: 'event' | 'incident' | 'workflow' | 'decision' | 'outcome';
  sourceEntityId?: string;
  
  // 波及先
  targetOrganizationId?: string;
  
  // 影響分類
  propagationType?: 'operational' | 'logistics' | 'staffing' | 'shipment' | 'community' | 'environment' | 'financial';
  
  severity?: 'low' | 'medium' | 'high' | 'critical';
  
  title?: string;
  description?: string;
  
  // 影響内容
  expectedImpact?: string;
  actualImpact?: string;
  
  detectedAt?: Timestamp;
  resolvedAt?: Timestamp;
  
  metadata?: {
    autoGenerated?: boolean;
    generatedBy?: string;
  };
  
  createdAt?: Timestamp;
}
```

### 波及例

```
Decision: ノリ出荷3日延期決定

Propagations:

1. Logistics Impact
   Type: shipment
   Target: 販売先卸売業者
   Severity: medium
   
   Expected Impact: "3日間の納期遅延"
   Actual Impact: "既存顧客への謝罪・代替品手配。
                  売上 ¥200k の移動。
                  新規顧客獲得での補補。"

2. Financial Impact
   Type: financial
   Target: 生産者組合
   Severity: medium
   
   Expected Impact: "売上遅延 ¥200k"
   Actual Impact: "実績: ¥180k遅延
                  ただし品質向上で単価+5%
                  最終的には +¥50k の売上増"

3. Community Impact
   Type: community
   Target: 地域産業全体
   Severity: low
   
   Expected Impact: "短期的な評判低下"
   Actual Impact: "「品質優先」の評判が定着。
                  長期的には顧客信頼度↑"
```
