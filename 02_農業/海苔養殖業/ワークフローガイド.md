**バージョン**: 1.0  
**有効日**: 2026-05-20

---

## 🎯 ワークフロー概要

このリポジトリでは、develop → main の構造化されたワークフローを採用しています。

```
feature branch
    ↓
develop (PR review)
    ↓
main (production)
```

---

## 📝 作業フロー

### 1. Feature ブランチを作成

```bash
git checkout develop
git pull origin develop
git checkout -b feature/nori-updates
```

**ブランチ名規則**:
- `feature/` - 新機能
- `docs/` - ドキュメント更新
- `fix/` - バグ修正
- `chore/` - メンテナンス

### 2. 変更を加える

```bash
# ファイル編集
vim 02_Agriculture/nori_farming_dss/your-doc.md

# 変更をステージング
git add 02_Agriculture/nori_farming_dss/

# コミット
git commit -m "docs: Your descriptive message"
```

### 3. Develop にプッシュして PR 作成

```bash
git push -u origin feature/nori-updates

# gh で自動的に PR テンプレートが表示されます
gh pr create --base develop
```

### 4. レビュー・マージ

- PR がレビューされます
- Develop にマージされます
- 定期的に develop → main へリリース PR が作成されます

---

## 📊 ブランチの役割

| ブランチ | 用途 | 状態 |
|---------|------|------|
| **main** | 本番・公開版ナレッジベース | 安定版 |
| **develop** | 機能開発・ドキュメント更新 | テスト環境 |
| **feature/*** | 個別の機能・ドキュメント | 開発中 |

---

## ✅ コミットメッセージの形式

```
type(scope): subject

body

footer
```

### 例

```
docs(nori): Add NORI_OS_QUICKSTART guide

Add comprehensive quick start guide for Nori farming DSS:
- 5-minute setup instructions
- Import and verification steps
- Troubleshooting FAQ
- Deployment guide

Closes #123
```

### Type の種類

- `feat`: 新機能
- `docs`: ドキュメント更新
- `fix`: バグ修正
- `refactor`: リファクタリング
- `chore`: メンテナンス
- `style`: コード整形

---

## 🔄 定期リリース

### 1-2週間ごと

```bash
# develop から main へのリリース PR を作成
git checkout main
git pull origin main
gh pr create --base main --head develop \
  --title "Release: Nori documentation updates" \
  --body "Latest updates from develop branch"
```
