# 海苔養殖 統合データ基盤ロードマップ

## 1. 目的

海況観測データ、水質、気象、河川、栄養塩、クロロフィル、漁場作業記録、収量・品質記録を統合し、海苔養殖の判断支援に使えるデータ基盤を構築する。

目指す状態は、単なるデータ蓄積ではなく、漁師さんが使える形で「いつ張るか」「どの漁場を警戒するか」「品質低下の兆候はあるか」「収穫判断を前倒しすべきか」を判断できるビューアと予測指標を作ることである。

## 2. 追加したいデータ

| データ | 主な用途 | 優先度 |
| --- | --- | --- |
| 降雨量 | 低塩分、河川流入、病害リスクの説明 | 高 |
| 河川水位・流量 | 出水影響、低塩分イベントの原因把握 | 高 |
| 栄養塩 | 色落ち、生育停滞、品質低下の説明 | 高 |
| クロロフィル | 植物プランクトン量、栄養塩競合、赤潮・水質変化の把握 | 高 |
| 透明度 | 濁り、光環境、出水影響の把握 | 中 |
| 日射量 | 光合成条件、乾燥・干出管理、成長条件の把握 | 中 |
| 風向風速 | 吹送流、波浪、作業可否、海水混合の把握 | 中 |
| 漁場作業記録 | 採苗、張り込み、摘採、網管理と環境の対応づけ | 高 |
| 収量・等級・色調・病害記録 | 環境データと成果の因果分析・予測モデル化 | 最高 |

## 3. データ統合の考え方

統合の基本単位は、まず「地点 x 日付」とする。水質データは時刻単位で細かいが、気象・河川・栄養塩・収量記録は日次または作業単位になる可能性が高いため、最初は日次集計に揃える。

将来的には、採苗・張り込み・摘採などの作業イベント単位で、直前3日、7日、14日の環境条件を特徴量として持たせる。

## 5. 分析で作りたい指標

| 指標 | 意味 |
| --- | --- |
| 高水温ストレス指数 | 23℃超、25℃超、継続日数を統合 |
| 低塩分ストレス指数 | 25‰未満、20‰未満、降雨・河川流量を統合 |
| 色落ちリスク指数 | 栄養塩、クロロフィル、透明度、日射、水温を統合 |
| 病害リスク指数 | 高水温、低塩分、DO低下、作業履歴を統合 |
| 採苗適期判定 | 水温3日移動平均、塩分、潮位、気象条件から判定 |
| 収穫前倒しシグナル | 高水温・低栄養・色調変化・病害兆候から判定 |

## 6. 優先順位

### Phase 1: すぐに統合する

- 降雨量
- 河川水位・流量
- クロロフィル
- 栄養塩
- 漁場作業記録
- 収量・等級・色調・病害記録

この段階で、水温・塩分・DOだけでは説明できなかった「なぜ色落ちしたのか」「なぜ品質が落ちたのか」に近づける。

### Phase 2: 精度を上げる

- 透明度
- 日射量
- 風向風速
- 潮流・流速
- 衛星データ

光環境、濁り、海水混合、漁場間の差を説明できるようにする。

### Phase 3: 予測・判断支援

- 採苗適期判定
- 漁期中のリスクアラート
- 色落ちリスク予測
- 病害リスク予測
- 収穫・網管理の推奨タイミング

## 7. Obsidianで管理するもの

Obsidianでは、データ本体ではなく、以下を管理する。

- データソース台帳
- 取得方法
- 更新頻度
- カラム定義
- 欠測・異常値ルール
- 分析レポート
- 判断ルール
- 現場ヒアリングメモ
- モデル改善履歴
