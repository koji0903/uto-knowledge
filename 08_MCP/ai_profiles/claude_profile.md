# Claude AI Profile

## 概要

Anthropic による大規模言語モデル。深い思考、複雑な推論、エッジケース対応が強み。

## 基本情報

| 項目 | 内容 |
|------|------|
| **組織** | Anthropic |
| **最新モデル** | Claude 4.6 (Sonnet) / 4.7 (Opus) |
| **特徴** | 長いコンテキスト、思考チェーン、安全性重視 |
| **推奨用途** | 深い分析、複雑な判断、矛盾検出 |

## 強み

### 1. 深い分析・推論
- 複雑な論理問題を段階的に分解できる
- 複数の視点から検討できる
- エッジケースや例外を見つけやすい

### 2. 長いコンテキスト活用
- 大量の背景情報を処理可能
- 文脈を失わない長編ドキュメント対応
- 部分的な更新から全体像を推論可能

### 3. 矛盾検出・品質保証
- ドキュメント間の不整合を指摘
- 前提条件の妥当性を検証
- ロジックギャップを発見

### 4. 倫理的判断
- 複数の価値観を考慮した判断
- リスク要因の多面的評価
- 慎重で責任ある提案

## 弱み・制限

| 弱み | 対策 |
|------|------|
| **リアルタイム情報に弱い** | Gemini に検索を依頼 |
| **最新ツール・API に遅れ** | ChatGPT に最新情報確認 |
| **単純タスクで過度に丁寧** | Gemini の方が効率的 |
| **実装コード生成は平均的** | ChatGPT の方が実装向け |

## Prompt Guide

### セットアップ（最初に提供）

```
あなたは uto-knowledge ナレッジシステムの分析担当 AI です。

## 役割
- 複雑な判断を支援する
- 矛盾やリスクを検出する
- 複数の視点から検討する
- 意思決定の根拠を明確にする

## アクセス可能な情報
- Obsidian Vault (README, AGENTS, 04_DataLink など)
- Firestore データ
- Google Drive ファイルへのリンク

## 制限事項
- 読み取りは全体可能
- 書き込みは AI運用ガイド.md の書き込みルールに従う
- Firestore 直接更新は不可（ログ記録後に User が apply）

## 推奨作業フロー
1. 関連ドキュメント・データを読み込む
2. 複数の角度から分析
3. 矛盾点・リスク・機会を列挙
4. 推奨アクション（複数案）を提示
5. 不確実な内容は 00_Inbox に下書き作成
6. 最終的な判断は User 確認後に実施
```

### 具体的なプロンプトパターン

#### パターン 1: 意思決定支援
```
【タスク】プロジェクト X の優先度判定

【背景】
- 現在のプロジェクト一覧: [リンク]
- 利用可能リソース: [詳細]
- 制約条件: [詳細]

【質問】
1. 各プロジェクトの重要度を分析してください
2. リスク要因を抽出してください
3. 複数の優先順位案を提示し、それぞれの長所・短所を述べてください
4. 最終推奨と根拠を述べてください

【出力形式】
- 分析結果 → 00_Inbox に下書き
- 最終的には User が 04_DataLink/decisions に記録
```

#### パターン 2: 品質保証・矛盾検出
```
【タスク】04_DataLink の整合性監査

【方法】
1. 以下をチェック：
   - Markdown frontmatter と Firestore document id の一致
   - relationships.md の参照先が実在するか
   - status が consistent か
   
2. 矛盾を見つけた場合：
   - どの矛盾か明確に
   - 影響範囲を判定
   - 修正案を複数提示

【出力】
04_DataLink/logs に監査ログを作成
```

#### パターン 3: システム設計検討
```
【タスク】新機能 X の導入検討

【要件】
[詳細を提供]

【検討項目】
1. 現在のアーキテクチャへの影響
2. Firestore スキーマの変更が必要か
3. MCP の設定変更が必要か
4. セキュリティ上の懸念
5. 運用上のリスク

【成果物】
- 00_Inbox または 04_DataLink/logs に検討結果を記録
- 複数の実装案を提示
```
