# Task Router: AI Selection Guide

どの AI がどのタスクに最適かを判定するルーティングガイド。

## クイック判定フロー

```
あなたのタスクを読んでください

        ↓
┌─────────────────────────────────┐
│ メインの活動は何ですか？        │
└─────────────────────────────────┘
        ↓
    ┌───┴───┬───────┬────────┐
    ↓       ↓       ↓        ↓
  分析   検索    実装    その他
   ↓       ↓       ↓        ↓
  CLU    GEM    GPT      判定表へ
  
CLU = Claude を選択
GEM = Gemini を選択
GPT = ChatGPT を選択
```

### E. 複合・判断困難系

| タスク内容 | 判定プロセス |
|-----------|------------|
| **複合タスク** | メインタスク（A-D）を特定してから判定 |
| 複数 AI が必要な場合 | リード AI を決め、サポート AI を指定 |
| 優先度が不明 | Claude に相談（複数案を評価） |
| 新しいツール活用 | ChatGPT に仕様確認後、実装 |
| 未知の領域 | Gemini で下調べ → Claude で戦略 → ChatGPT で実装 |

## 判定フロー（詳細版）

### フロー 1: 意思決定サポート

```
┌─ タスク: 重要な判断が必要
│
├─ 複数の案を比較したいか？
│  ├─ YES → Claude（複数視点分析）
│  └─ NO → 次へ
│
├─ 外部データ・市場情報が必要か？
│  ├─ YES → Gemini で検索 → Claude で分析
│  └─ NO → Claude
│
└─ 意思決定 → Claude を選択
```

### フロー 2: 情報・リサーチ

```
┌─ タスク: 情報が必要
│
├─ 外部（Web、最新）情報か？
│  ├─ YES → Gemini（Web 検索可）
│  └─ NO → 次へ
│
├─ Google Drive / Workspace か？
│  ├─ YES → Gemini（直接アクセス）
│  └─ NO → 次へ
│
├─ PDF / 画像処理か？
│  ├─ YES → Gemini（マルチモーダル）
│  └─ NO → Claude（テキスト分析）
│
└─ 情報収集 → Gemini を選択
```

### フロー 3: 実装・スクリプト

```
┌─ タスク: 何かを作る・実装する
│
├─ コード生成が必要か？
│  ├─ YES → ChatGPT（実装知識豊富）
│  └─ NO → 次へ
│
├─ bash / Python スクリプトか？
│  ├─ YES → ChatGPT（スクリプト最適化）
│  └─ NO → 次へ
│
├─ ドキュメント・資料か？
│  ├─ YES → ChatGPT（テンプレート、生成）
│  └─ NO → 設計検証なので Claude
│
└─ 実装 → ChatGPT を選択
```

## リード AI とサポート AI の組み合わせ

### パターン 1: 意思決定 + 市場情報

```
タスク: プロジェクト投資判定

リード: Claude
  - 複数の投資案を分析
  - リスク評価
  - 長期的な影響

サポート: Gemini
  - 市場トレンド調査
  - 競合情報
  - 技術動向

流れ:
  1. Gemini が市場情報を収集
  2. Claude が分析・判定
  3. 決定ログに記録
```

### パターン 2: 設計 + 実装

```
タスク: 新機能実装計画

リード: Claude
  - アーキテクチャ設計
  - インターフェース設計

サポート 1: ChatGPT
  - 実装パターン提案
  - コード生成

サポート 2: Gemini
  - 最新ライブラリ確認
  - API 仕様確認

流れ:
  1. Claude が設計
  2. ChatGPT が実装案
  3. Gemini が最新情報確認
  4. Claude が検証
  5. 実装開始
```

### パターン 3: リサーチ + 分析 + 実装

```
タスク: 外部システム連携実装

リード: Gemini
  - 外部システム仕様調査
  - API ドキュメント確認

サポート 1: Claude
  - 実装戦略立案
  - リスク分析

サポート 2: ChatGPT
  - API クライアント実装
  - テストコード

流れ:
  1. Gemini がリサーチ
  2. Claude が戦略立案
  3. ChatGPT が実装
  4. 反復
```

## タスク記録テンプレート

大事なタスクは、以下の形式で `00_Inbox` / `04_DataLink/logs` に記録してください：

```markdown
---
id: task_20260503_001
type: task
primary_ai: [Claude / Gemini / ChatGPT]
secondary_ai: []
status: planning
---

# タスク: [タイトル]

## 背景
[なぜこのタスクが必要か]

## 判定プロセス
[どの判定フロー / 判定表を使ったか]

## 選択した AI と理由
- Primary: [AI] - [理由]
- Secondary: [AI] - [理由]

## 期待される成果物
[具体的な出力]

## 実施予定
[いつ、誰が（User / AI）実施するか]

## 進捗
- [ ] リード AI が主タスク完了
- [ ] サポート AI が補助完了
- [ ] User が確認・承認
- [ ] 最終ログ作成
```

## AI 選択のアンチパターン

### ❌ 避けるべき組み合わせ

| 組み合わせ | 理由 | 改善 |
|-----------|------|------|
| 複雑な分析を Gemini だけで | 深掘り分析ができない | Claude を加える |
| 実装を Claude だけで | 実装コードがぎこちない | ChatGPT を加える |
| ニュース情報を Claude で検索 | 古い情報になる | Gemini で検索 |
| 新しいツール情報を ChatGPT だけで | 実装には問題ない、ただし古いかも | Gemini で最新確認 |
| すべてを 1 つの AI にやらせる | 非効率、品質低下 | 得意分野に分割 |

## よくある質問

### Q1: 複雑なタスク、どうやって決めるか？

A: 

1. タスクを複数のサブタスクに分割
2. 各サブタスクに最適な AI を割り当て
3. リード AI を決定
4. 流れを計画

```
例：
タスク: 新商品ローンチ計画

分割:
- サブ 1: 市場調査 → Gemini
- サブ 2: 戦略立案 → Claude
- サブ 3: 実装計画 → ChatGPT
- リード: Claude（全体統括）
```

### Q2: 意見が分かれたら？

A: 複数 AI の意見の相違は**価値**。両者の判定を記録：

```markdown
# 意見相違

## 課題
[何について意見が分かれたか]

## Claude の見方
[分析結果]

## Gemini / ChatGPT の見方
[別の視点]

## 評価
- 採択案: [選んだ方]
- 理由: [なぜ採択したか]
- 学習: [今後の判定の参考]
```

### Q3: 新しいタスクタイプが出たら？

A: このドキュメント更新候補。User に相談：

```
mcp/ai_profiles/feedback/ に
「新しいタスク: xxx, 推奨 AI: yyy, 理由: zzz」
と記録
```
